*VISION*  (v0.3 draft - 2026-07-24)

I'm building a multi-timeframe futures day trading system that gives me trade signals across different timeframes and different instruments, all off one cohesive strategy. Price action is fractal - it repeats across all timeframes. The higher timeframes may point a different direction than the lower ones, and that's fine - a HTF trend can give me opposite scalping trades on the LTF. I want to see all of that at once.

The strategy itself comes from Stoic Traders. I am NOT inventing a new strategy or "improving" it. The edge is the strategy; the code just executes it consistently without me getting emotional.

***Signals only (for now)***
The system generates and tracks signals - it does NOT place orders. No broker/execution API yet. It tells me the trade; I place it. The ledger tracks each signaled trade to its outcome. Automated execution is a later phase, not now.

***What the SLM does vs what generates signals***
This part matters, don't mix them up.
- The live signal code is deterministic rules. It MUST NOT call an LLM/SLM to decide a trade. Same inputs, same signal, every time. I need to be able to trust and audit it.
- The SLM is a research/offline tool only. Use it to mine the education, label setups, help me turn the videos into concrete rules, sanity-check my logic. It never sits in the live path.
So: SLM helps me build the rulebook. The rulebook (plain code) makes the calls.

***What a signal actually is***
Every signal is one record with at least: instrument, Type (Scalp/Day/Swing/Position), direction (long/short), entry, stop, target, R multiple, setup type, confidence, signal timestamp, and source (which system produced it). Confidence is a deterministic confluence score computed by the rules - not a model output. If I can't fill these in, it's not a signal yet.

***How I know it works***
+Backtest, walk-forward and paper are how I measure the edge - expectancy, win rate, average R, and max drawdown per timeframe and per instrument. Because v1 is signals-only (nothing risks capital), this validation runs in parallel and does NOT gate going live with signals/dashboard.

***Trade ledger***
One trade ledger per Type (Scalp/Day/Swing/Position), kept in Google Drive as the source of truth. Multiple systems may write to it, so trade id, timestamp and source are required on every row. Because of the concurrent writers, don't have them all edit one shared file live - append-only, or a file per source that gets reconciled. Losing or corrupting the ledger is not acceptable.

Timestamps: everything I look at is Pacific time, but stored in UTC. Convert at the edges only. The flatten cutoff uses current Pacific wall-clock time, so DST is handled automatically - no fixed UTC offset.

Each signaled trade is tracked till close - take profit or stop loss. Only Position-type trades can stay open past NY trading hours; every other Type is flattened (marked closed at market) at 1:58pm Pacific. This cutoff must hold even if a process died earlier, so it needs a watchdog/heartbeat that guarantees the flatten happens.
